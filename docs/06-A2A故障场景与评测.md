# A2A 故障场景与评测

## 1. 评测目标

评测同时回答两个问题：A2A 是否按契约稳定完成任务；拆分 Agent 是否带来可测量的质量或恢复收益。single、a2a、offline 使用相同黄金集、规则版本、模型参数、预算和安全策略，不能只比较最终文本。

## 2. 故障注入矩阵

| 场景 | 注入方式 | 期望结果 | 关键指标 |
|---|---|---|---|
| Agent Card 缺少能力 | 删除 `impact` capability | 不创建子任务，返回版本/能力错误 | 路由拒绝正确率 |
| 协议版本不兼容 | Agent 只支持 `0.2` | 返回 `PROTOCOL_VERSION_UNSUPPORTED` | 协商记录完整率 |
| 子任务超时 | 延迟响应超过 45 秒 | 查询状态，最多重试一次，最终收敛 | 超时收敛率 |
| SSE 断线 | 丢弃中间事件 | 从游标或轮询恢复 | 事件恢复率 |
| Artifact Schema 非法 | 缺少必填字段 | 拒绝入库，父任务不前进 | Schema 拦截率 |
| Artifact 哈希错误 | 修改内容不改 hash | 返回 `ARTIFACT_HASH_MISMATCH` | 完整性拦截率 |
| 重复提交 | 重放相同幂等键 | 返回原结果，无重复副作用 | 重复副作用次数 |
| Coordinator 重启 | 子任务 working 时终止进程 | 从数据库恢复并继续或转人工 | 恢复成功率 |
| Agent 越权 | Review 请求 `write_patch` | 返回 `PERMISSION_DENIED` | 越权成功次数 |
| Verify 失败 | 测试失败或覆盖率下降 | 不进入审批，保留证据 | 质量门禁正确率 |

## 3. 指标定义

| 指标 | 定义 | MVP 目标 |
|---|---|---:|
| A2A 任务路由正确率 | 实际 Agent 与期望 Agent 匹配的子任务数 / 总子任务数 | ≥95% |
| Artifact Schema 通过率 | 通过类型、版本、字段和哈希校验的 Artifact / 总 Artifact | ≥98% |
| 父子任务收敛率 | 在 deadline + 1 次重试内进入终态的子任务 / 总子任务 | ≥95% |
| Coordinator 恢复成功率 | 重启后不重复执行且恢复到正确状态的任务 / 重启任务 | 100% |
| Trace 完整率 | 可关联父任务、子任务、消息、Artifact 和工具事件的链路 / 总链路 | ≥95% |
| 评测可重复率 | 相同输入和版本得到相同确定性结果的运行 / 总运行 | 100% |
| 审查召回率/精确率 | 命中标注缺陷的 Finding / 标注缺陷；正确 Finding / 全部 Finding | ≥80% / ≥70% |
| pass@3 / pass^3 | 三次运行至少一次成功 / 三次全部成功 | ≥85% / ≥70% |
| 安全不变量 | 越权写入、未审批合并、重复副作用、沙箱逃逸 | 均为 0 |

## 4. single 与 a2a 对照实验

每个黄金用例分别运行 single、a2a、offline 三种模式，每种模式 3 次。固定输入 Diff、上下文策略、规则版本、模型、温度、Token 预算和沙箱参数；随机顺序执行，避免先后顺序影响。

记录以下结果：最终 Finding/补丁/验证是否正确、子任务路由、Artifact 校验、工具轨迹、Token、端到端延迟、重试次数、恢复结果和安全不变量。报告同时展示绝对值与 a2a 相对 single 的变化，不以“Agent 数量”作为效果证明。

建议结论门槛：a2a 的审查精确率和安全指标不得低于 single；若 a2a 延迟增加超过 30%，必须解释为协议与并行度成本；只有在质量、恢复或可观测性至少一项提升且安全不退化时，才保留拆分收益结论。

## 5. 评测用例扩展字段

```json
{
  "mode_expectations": {
    "modes": ["single", "a2a", "offline"],
    "expected_agents": ["review-agent", "impact-agent", "fix-agent", "verify-agent"],
    "expected_artifacts": ["Finding", "ImpactReport", "PatchCandidate", "VerifyEvidence"],
    "max_child_tasks": 4,
    "recovery_required": false
  }
}
```

故障用例将 `recovery_required` 设为 `true`，并在报告中记录注入点、恢复动作、最终状态和是否产生副作用。
