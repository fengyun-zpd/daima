## 2. 3 分钟演示（最小可信闭环）

目标：证明"提交 diff → 规则审查 + 影响分析 → 父任务收敛到 REVIEWED → 幂等与审计可回放"。

```powershell
# 0) 启动单进程形态
Copy-Item .env.example .env -ErrorAction SilentlyContinue
docker compose up -d postgres api web
docker compose run --rm sandbox-image        # 只需第一次
(Invoke-RestMethod http://127.0.0.1:8099/readyz) | ConvertTo-Json -Depth 4
#   → status=ready、agents 四类、tools 8 个、transport=inprocess

# 1) 创建审查任务（真实 HTTP API，含硬编码密钥 / shell=True / SQL 拼接）
$diff = @'
diff --git a/app/config.py b/app/config.py
--- a/app/config.py
+++ b/app/config.py
@@ -1,6 +1,9 @@
 import os
 import subprocess
 import sqlite3

 def load_user(conn, name):
+    API_KEY = "sk-live-0123456789abcdef"
+    subprocess.run("ls " + name, shell=True)
+    return conn.execute("SELECT * FROM users WHERE name = '" + name + "'").fetchall()
'@
$headers = @{ "X-Actor-Id" = "dev-1"; "X-Actor-Role" = "developer"; "Idempotency-Key" = "demo-0000001" }
$body = @{ input_type = "diff"; content = $diff; base_commit = "synthetic-base-001"; context_policy = "function"; mode = "a2a" } | ConvertTo-Json
$created = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8099/api/v1/reviews -Headers $headers -ContentType "application/json" -Body $body
$task = $created.task.id; $task
#   → created=true，返回 task_id 与 trace_id

# 2) 查看审查结果（Finding / 影响面 / 子任务 / 审计尾部）
Start-Sleep -Seconds 2
$detail = Invoke-RestMethod -Uri "http://127.0.0.1:8099/api/v1/reviews/$task" -Headers @{ "X-Actor-Id"="dev-1"; "X-Actor-Role"="developer" }
$detail.task.status                     # REVIEWED
$detail.comments | Select-Object rule_id, severity, file, line, auto_fixable
$detail.child_tasks | Select-Object task_type, agent_id, status, attempt, transport
$detail.artifacts | Select-Object artifact_type, content_hash, validated
$detail.task.summary.risk_level; $detail.task.summary.affected_files

# 3) 幂等重放：同键同请求必须返回原任务，不产生第二份副作用
$again = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8099/api/v1/reviews -Headers $headers -ContentType "application/json" -Body $body
$again.created; ($again.task.id -eq $task)     # False / True
```

浏览器打开 <http://127.0.0.1:8080>，把 `$task` 粘到"任务 ID"输入框 → 加载，即可看到同一份
Finding、时间线、Artifact 与审计。

**这 3 分钟证明了**：真实 HTTP 闭环、父子任务、规则与影响分析、trace 串联、幂等重放、Dashboard 可用。

## 3. 10 分钟完整演示（Fix → 沙箱 → 审批 → 合并 → 审计）

接着 §2 继续（同一个 `$task`）。

### 3.1 生成候选补丁（Fix）

```powershell
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8099/api/v1/reviews/$task/fixes" `
  -Headers @{ "X-Actor-Id"="dev-1"; "X-Actor-Role"="developer"; "Idempotency-Key"="demo-fix-0001" }
Start-Sleep -Seconds 3
$detail = Invoke-RestMethod -Uri "http://127.0.0.1:8099/api/v1/reviews/$task" -Headers @{ "X-Actor-Id"="dev-1"; "X-Actor-Role"="developer" }
$detail.task.status              # FIXING → TESTING → PENDING_APPROVAL / NEEDS_HUMAN
$patches = Invoke-RestMethod -Uri "http://127.0.0.1:8099/api/v1/reviews/$task/patches" -Headers @{ "X-Actor-Id"="dev-1"; "X-Actor-Role"="developer" }
$patch = $patches[-1]
$patch | Select-Object patch_version, patch_hash, status, fix_category, target_branch, changed_files, scope_drift, wide_impact
$patch.diff                      # 只改选定 Finding 允许的文件
```

要点：Fix 只生成候选补丁，**不写任何文件**；`patch_hash` 可由 `diff` 重算（见 `tests/test_scenario_fix_flow.py`）。

### 3.2 查看验证证据（Verify，真实 Docker 沙箱）

```powershell
$detail.task.summary.verify_evidence | ConvertTo-Json -Depth 5
#   sandbox_degraded=false（真实沙箱）、apply_check.ok=true、
#   tiers=[prescan / apply_check / lint / unit_test / regression / coverage]
$detail.task.summary.gate_failure       # 仅在门禁未通过时出现，说明是哪一层没过
```

只看 diff 输入时工作区没有测试文件，`unit_test` 层会失败 → 父任务落到 `NEEDS_HUMAN`（这是
**正确的保守行为**：宁可不合并）。想看到走到 `PENDING_APPROVAL` 的完整链路，用带测试的 ZIP 输入：

```powershell
# 演示数据自带可运行测试，因此 Verify 能给出真实覆盖率证据
python scripts/seed_demo.py --base-url http://127.0.0.1:8099    # 通过 API 触发（后台执行）
python scripts/seed_demo.py                                     # 或在当前进程内直接跑完整链路
python -m pytest tests/test_scenario_fix_flow.py -q             # 含真实沙箱的 Fix→审批→合并全链路
```

### 3.3 审批（只有 approver/admin 能批，且绑定 patch_version）

```powershell
# developer 审批必须被拒绝
try {
  Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8099/api/v1/fixes/$($patch.id)/approval" `
    -Headers @{ "X-Actor-Id"="dev-1"; "X-Actor-Role"="developer"; "Idempotency-Key"="demo-appr-dev1" } `
    -ContentType "application/json" -Body '{"decision":"approve","patch_version":1,"reason":"ok"}'
} catch { $_.Exception.Response.StatusCode.value__ }     # 403

# 旧版本审批必须被拒绝（VERSION_CONFLICT）
# approver 批准
$approve = Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8099/api/v1/fixes/$($patch.id)/approval" `
  -Headers @{ "X-Actor-Id"="approver-1"; "X-Actor-Role"="approver"; "Idempotency-Key"="demo-appr-0001" } `
  -ContentType "application/json" -Body (@{ decision="approve"; patch_version=$patch.patch_version; reason="证据充分，影响范围符合预期" } | ConvertTo-Json)
$approve
```

### 3.4 合并到任务分支（审批通过后才允许）

```powershell
$merge = Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8099/api/v1/fixes/$($patch.id)/merge" `
  -Headers @{ "X-Actor-Id"="approver-1"; "X-Actor-Role"="approver"; "Idempotency-Key"="demo-merge-0001" } `
  -ContentType "application/json" -Body (@{ patch_version=$patch.patch_version } | ConvertTo-Json)
$merge       # branch=codepilot/<task_id>，commit=<sha>，task_status=MERGED

# 幂等重放：同键同请求返回同一个 commit，并标注 idempotent_replay
$replay = Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8099/api/v1/fixes/$($patch.id)/merge" `
  -Headers @{ "X-Actor-Id"="approver-1"; "X-Actor-Role"="approver"; "Idempotency-Key"="demo-merge-0001" } `
  -ContentType "application/json" -Body (@{ patch_version=$patch.patch_version } | ConvertTo-Json)
$replay.idempotent_replay; ($replay.commit -eq $merge.commit)      # True / True
```

### 3.5 审计与 trace 回放（仅 admin）

$audit = Invoke-RestMethod -Uri "http://127.0.0.1:8099/api/v1/audit?task_id=$task&limit=100" `

$audit | Select-Object event_type, actor_role, entity_type, state_version, error_code | Format-Table

## 5. 每一步"该看到什么"（自查表）

| 步骤 | 期望结果 | 失败时看哪里 |
|---|---|---|
| `/healthz` | `{"status":"ok"}` | `docker compose logs api` |
| `/readyz` | `status=ready`、4 个 agent、8 个 tool、`transport` 明确 | 数据库不可达 / Card 校验失败会在启动日志报错 |
| 创建任务 | `created=true` + `task_id` + `trace_id` | 400 `INVALID_INPUT`（diff 非法）、400 `IDEMPOTENCY_KEY_REQUIRED` |
| 审查完成 | `status=REVIEWED`，2 个子任务 `completed`，Artifact `validated=true` | `NEEDS_HUMAN` 时看 `error_code` 与 `audit_tail` |
| 触发 Fix | `FIXING → TESTING → PENDING_APPROVAL` | `NEEDS_HUMAN` + `PATCH_INVALID`（无法安全改写） |
| VerifyEvidence | `sandbox_degraded=false`、`apply_check.ok=true`、`tiers` 齐全 | `SANDBOX_UNAVAILABLE`（Docker/镜像缺失）、`gate_failure`（哪层没过） |
| 审批 | developer 403；approver 200；旧版本 `VERSION_CONFLICT` | `ILLEGAL_STATE_TRANSITION`（状态不是 PENDING_APPROVAL） |
| 合并 | `task_status=MERGED`、`branch=codepilot/<task>`、`commit=<sha>` | 403 `FORBIDDEN`（没有绑定该版本的审批） |
| 审计 | admin 可见、developer 403、事件按 trace 串联 | `AuditEvent` 表只允许 INSERT |
| Dashboard | 创建/加载任务、看到 mode 与 transport、按钮按角色与状态禁用 | `python scripts/check_dashboard_e2e.py` |

## 6. 常见失败处理

| 现象 | 处理 |
|---|---|
| `docker compose up` 报端口被占用 | 换端口（override + `!override`）或停掉占用进程 |
| `docker compose build` 报 sharedkey 非打印字符 | `$env:COMPOSE_BAKE="0"; docker compose build api web` |
| `SANDBOX_UNAVAILABLE` | `docker compose run --rm sandbox-image`；确认 `docker images` 有 `codepilot-sandbox:local` |
| `SANDBOX_TIMEOUT` / `QUALITY_GATE_FAILED` | 正常门禁结果：看 `verify_evidence.tiers` 与 `sanitized_output`；不写分支、转人工 |
| Dashboard 打开是 502 | api 容器没起来，或 nginx 缓存了旧 IP（当前实现已用 `resolver` 每次重解析，重建 api 后无需重启 web） |
| Dashboard 打开是空白页 | 后端不可达时页面显示"API 未就绪"；用 `python scripts/web_check.py` 与浏览器控制台确认 |
| PowerShell 里 `curl` 行为异常 | 用 `Invoke-RestMethod` / `Invoke-WebRequest`（本文件统一使用） |
| 任务一直 `REVIEWING` | 后台编排线程在跑；确认 `CODEPILOT_RECOVER_ON_START`、看 `audit_tail`，或对同一 task 重新 `POST /reviews`（幂等返回原任务） |
| 幂等键冲突 | 同键必须同请求；换一个键表示新的命令（Dashboard 会自动为"新的一次操作"生成新键） |

## 7. Docker 不可用时怎么演示（如实说明）

Docker 不可用时**不要**假装沙箱验收通过。可以这样演示与说明：

1. **仍然可演示**：创建任务 → 规则审查 → 影响分析 → Finding/Artifact → 幂等重放 → 审计 → Dashboard。
2. **触发 Fix 后**会得到 `NEEDS_HUMAN` + `SANDBOX_UNAVAILABLE`，并在 `verify_evidence` 里看到
   `sandbox_degraded=true` 与原因；系统**不会**改在宿主机执行提交代码（宪法第八条）。
3. 静态沙箱契约与降级测试仍然可跑：

```powershell
python -m pytest tests/test_phase6_fix_verify.py -q -k "refuses_without_sandbox or blocks_dangerous or test_gap"
python -m pytest tests/test_scenario_fix_flow.py -q
python scripts/run_checks.py --fast      # 结论会写 "Docker not executed"
```

4. 报告中必须写成：**"静态 Compose 契约通过 / HTTP A2A 测试通过 / 真实容器与沙箱验收未完成"**，
   不能写成"沙箱验收通过"。

## 8. 交付边界（演示时对外说清楚）

- 服务端输入是**diff / ZIP**；可用 `scripts/review_local_repo.py` 从本地 Git 的 `base..head` 只读生成 diff，仍不接 GitHub/GitLab 生产 OAuth；
- 生成层默认是**确定性 provider**（不联网）；`offline` 模式连生成层都不调用，**不生成补丁**；
- A2A 的拆分形态是**一个统一的 Agent 服务进程**，不是四类 Agent 各自一个容器；
- 任务分支是内容目录下的**合成 Git 仓库**（`var/repos/<task_id>`），不是真实远端仓库；
- 本地 Git 适配器不会修改调用方当前目录；`--merge` 只写 CodePilot 的隔离任务分支并导出 commit/patch；
- Dashboard 目前用**轮询**（2 秒，终态自动停止），SSE 端点已具备但未接入页面；
- 幂等台账 `idempotency_record` **只增不删**，没有 TTL/归档；
- 鉴权是**请求头身份**，没有 OAuth/JWT/多租户；Docker Socket 挂载只适合本地开发；
- 明确的"不做"清单见宪法第十一条与 README §1.5。
